Testing Guide

Test layers

  1. Unit tests validate normalization, collectors, identity rules, claims, state, graph construction, diff, and rendering.
  2. Integration tests validate coordinator lifecycle, output publication, launcher scripts, and archive behavior.
  3. Production-shaped fixtures reproduce vendor and topology conditions such as Nexus VDCs, strict Cisco endpoints, incomplete tables, reused addresses, transparent protocol forwarding, and virtual workloads.
  4. Two consecutive live runs validate behavior under real timing, SNMP agents, DNS, and topology variance.

Required local checks

python -m compileall -q src tests scripts
pytest -q
find scripts -type f -exec sh -c '
  for file do
    case "$(head -n 1 "$file")" in
      *bash*) bash -n "$file" ;;
    esac
  done
' sh {} +

Run the complete static gate when installed:

ruff check
ruff format --check
ty check

Record unavailable tools as not run; do not report them as passes.

Graph release gates

  • Every immutable advertisement is materialized or explicitly excluded.
  • Replaying the same evidence is idempotent.
  • Randomized input order produces equivalent semantic output.
  • Retiring a provisional host does not erase evidence.
  • Same VDC across multiple routes remains one logical entity.
  • Sibling VDCs sharing a chassis remain separate logical entities.
  • 1:1, 1:N, N:1, and N:M correspondence are tested.
  • A superseding decision retains history.
  • Coverage failure does not become a confirmed removal.
  • Run-local IDs and volatile table indexes do not control semantic IDs.

Release artifact checks

  • Patch applies cleanly to the exact base archive.
  • Patched tree matches the staged source tree.
  • Archive extracts under one versioned root.
  • Extracted tree matches the staged tree.
  • Tests and compile checks pass from the fresh archive.
  • No .git, virtual environment, cache, bytecode, build, or distribution artifacts are packaged.
  • SHA-256 hashes are generated after final artifact creation.

Sanitized-example regression

tests/test_sanitized_examples.py scans every shipped UTF-8 file for previously removed operation-derived identifiers. The deny set is stored as digests, so the test does not preserve readable customer values. It also verifies that operator documentation uses approved example DNS and IP namespaces.

When adding a production-shaped regression, rematerialize it with synthetic names, addresses, serials, endpoint identifiers, run IDs, credentials, and tag labels before committing it. Preserve the relationships and conflict behavior that make the fixture useful, not the originating environment's identifiers.
