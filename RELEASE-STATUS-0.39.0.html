0.39.0 acceptance contract

1. Install layouts — complete

paths.persistent_root = "auto" and paths.scratch_root = "auto" no longer pick the first existing ~/lldp-runner, /opt/lldp-runner, or /var/lib/lldp-runner for each user. lldp_runner.layout derives both roots from the primary configuration file as it was named:

/opt/lldp-runner/config.toml    /opt/lldp-runner/var     /dev/shm/lldp-runner
/etc/lldp-runner/config.toml    /var/lib/lldp-runner     /run/lldp-runner
~/lldp-runner/config.toml       ~/lldp-runner/var        $XDG_RUNTIME_DIR/...
  • Any other <dir>/config.toml outside the home directory is a shared install with data in <dir>/var and its own scratch name, such as /dev/shm/lldp-runner-srv-lab. Every layout falls back to <persistent_root>/tmp for scratch.
  • Without a configuration file, the first installation present wins: /opt/lldp-runner, then /var/lib/lldp-runner or /etc/lldp-runner, then ~/lldp-runner. A present installation whose data directory is missing or unwritable is an error, never a fallback to the home directory.
  • Data sits in var/ because discovery write-tests its persistent root; a group-writable installation directory would let operators add files that the maintainer or the service account later loads.
  • Shared and system roots are never created on demand. /tmp/lldp-runner and /var/tmp/lldp-runner are no longer scratch candidates.
  • Installations that still keep runs/ and outputs/ directly in the installation directory keep using them until var/ exists. Unused history beside var/, or in ~/lldp-runner, is reported by paths, validate-config, and run.
  • lldp-runner paths [--json] and scripts/lrun-paths show the layout and every location without creating anything.

2. Launchers and helper scripts — complete

  • The lrun-* launchers embed no installation path. They select LLDP_RUNNER_CONFIG from .private, then <project>/config.toml, then /etc/lldp-runner/config.toml, then an inherited LLDP_RUNNER_CONFIG, so an operator's personal setting cannot move a shared launcher onto another installation. They start in that file's directory, run through uv run --project, and run the installed lldp-runner when there is no pyproject.toml beside them.
  • lrun-bundle-diff reads its source directories from lrun-paths.
  • svc-setup.sh gives the units a uv cache in /var/cache/lldp-runner/uv. example.private sets UV_NO_CACHE=1 when ~/.cache/uv cannot be created and keeps umask 0022 for the maintainer.

3. Root-run setup safety — complete

An independent review of the layout change found that shared-setup.sh ran install -d, chmod, and setfacl as root inside group-writable runtime directories, so a planted var/tmp symlink could make another directory group-writable on the next run. It now locks each runtime root to root-only access while it works below it; refuses symlinks, foreign owners, and group- or world-writable parents; walks existing content only with --repair; and refuses to create var/ beside older runs/ or outputs/ unless --migrate moves them. It no longer re-owns an existing Python directory.

4. Seed initialization fix — complete

An unparseable seed, such as 127.0.0.1, raised UnboundLocalError and aborted run initialization. It is now recorded as an invalid_seed error and counted as skipped. The new regression test fails on the old code.

5. Documentation — complete

docs/INSTALL.md describes the three layouts and the folders each one uses, installs the shared Python as root with /etc/uv/uv.toml and /etc/profile.d guard rails, removes group write and world access from the installation, replaces the ineffective conf.d paths step, documents upgrades and the move into var/, and lists the tzdata prerequisite. README, CLI, ENVIRONMENT, ARCHITECTURE, and developer docs follow the new behavior.

6. Behavior otherwise unchanged

Collection, worker, retry, credential, classification, topology, output, diff, watch, and schema logic did not change.

7. Release metadata — complete

The application version is 0.39.0. The constraints manifest moved to constraints/release-0.39.0.txt with identical pins, and the release test now rejects a leftover release-0.38.1.txt.

Upgrade notes

  • Shared installs with paths = "auto": data now lives in /opt/lldp-runner/var. Stop the timers, make the installation root not group-writable, and run scripts/shared-setup.sh --group netops --migrate to move runs/, outputs/, and tmp/ into var/ (INSTALL.md, "Moving data into var/"). Until then the old location keeps working with a warning.
  • Explicit [paths]: unaffected.
  • Scheduled installs: run svc-remove.sh and then svc-setup.sh. The boot-time scratch entry is now /etc/tmpfiles.d/lldp-runner-scratch.conf, maintained by shared-setup.sh.
  • Runs without a configuration file now use the installation present on the host instead of the first existing per-user candidate.
