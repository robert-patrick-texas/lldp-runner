0.37.0 acceptance contract

1. PySNMP built-in default — complete

An omitted snmp.backend setting now resolves to pysnmp. One canonical DEFAULT_SNMP_BACKEND constant supplies the built-in configuration, operator-facing active-command help, generated-configuration comments, and the safe default for directly constructed run-manifest provenance.

2. Explicit Gufo support and precedence — complete

gufo remains a valid explicit backend in TOML, the LLDP_RUNNER_SNMP_BACKEND environment variable, repeatable --set expressions, and the dedicated --snmp-backend option. Existing precedence is unchanged: built-in default, assembled TOML, environment, --set, then dedicated CLI. An explicit Gufo setting always overrides the new implicit PySNMP default at the appropriate precedence level.

3. Immutable run and resume behavior — complete

The selected backend remains fixed before discovery and throughout every worker and resume. A new run using the implicit default persists pysnmp and resumes under the same implicit default. A durable Gufo run cannot resume when an omitted setting resolves to PySNMP; the mismatch fails before discovery or run manifest mutation. Selecting Gufo explicitly permits that Gufo resume.

No automatic fallback, backend conversion, or mixed-backend operation was introduced.

4. Configuration and operator surface — complete

The checked-in example, generated configuration, CLI help, environment guide, precedence guide, run guide, installation guide, SNMP guide, architecture, README, testing guide, schema reference, changelog, and examples identify PySNMP as the default. Migration guidance tells operators to retain or add an explicit Gufo selection before resuming an existing Gufo run.

5. Read-only and credential boundaries — complete

Read-only commands continue to load configuration with credentials disabled and do not select, import, preflight, or construct either network backend. The backend default change does not alter shared credential semantics or the backend-specific Gufo/PySNMP capability maps.

6. Backend implementation boundaries — complete

No Gufo adapter, PySNMP adapter, backend factory, cryptography preflight, warning filter, transport, collector, worker, retry, topology, output, diff, or watch implementation changed. PySNMP still uses retries=0, and LLDP-Runner remains the sole retry owner. Gufo remains available as the explicit rollback backend.

7. Release metadata and schemas — complete

The application version is 0.37.0. Dependency minimums and exact Linux pins are unchanged from 0.36.3. No machine-readable schema changed merely because the default backend changed.
